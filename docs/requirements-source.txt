Kamu adalah software engineer senior dengan keahlian React, TypeScript, Go, PostgreSQL, aplikasi web, pengolahan laporan, dan desain UI/UX dashboard. Bangun aplikasi bisnis livestreaming “Its My Live” berdasarkan persyaratan berikut dan seluruh Lampiran BRD.
Kerjakan source code sampai bisa dijalankan dan diuji di localhost. Jangan berhenti pada proposal, diagram, struktur folder kosong, mockup, atau tombol tanpa fungsi. Selesaikan bertahap, verifikasi tiap tahap, lalu lanjutkan tanpa meminta konfirmasi untuk keputusan implementasi rutin.

Urutan prioritas:
1. Integritas data dan kontrol akses.
2. Alur upload, review, publikasi, dan revisi.
3. Ketepatan agregasi dan leaderboard global.
4. UI minimal, responsif, mudah dipakai.
5. Integrasi OpenClaw dan insight.

Periksa folder project dan konfigurasi yang sudah ada sebelum mengubah file. Jangan merusak pekerjaan pengguna. Gunakan branch terpisah jika project memakai Git dan sesuai instruksi repository.
Buat docs/implementation-plan.md dan docs/decisions.md. Catat keputusan teknis, asumsi, status setiap fitur, dan persyaratan yang belum dapat diverifikasi. Tidak perlu meminta keputusan pengguna untuk pilihan rutin yang sudah memiliki default di sini.
Periksa versi Go, Node.js, npm, PostgreSQL, Docker Compose, dan OpenClaw yang tersedia. Pilih versi dependency yang kompatibel dan pin dalam manifest/image tag. Jangan mengarang versi terbaru, endpoint SDK SapaGo, atau format konfigurasi OpenClaw. Verifikasi dokumentasi resmi untuk API eksternal.

Room dapat memiliki beberapa slot berurutan; satu slot MVP memiliki satu host.
2. Stack dan arsitektur yang dipakai
- Server dan backend: Go, modular monolith.
- HTTP: net/http; pilih router kecil hanya jika dibutuhkan.
- Frontend: React + TypeScript + Vite, single-page application dengan TSX.
- Routing: React Router dengan layout nested dan halaman sesuai permission.
- Server state: TanStack Query untuk fetch, mutation, invalidation, dan status loading/error.
- UI: komponen React reusable, CSS design tokens/CSS Modules, accessible dialog/drawer/form.
- Grafik: Chart.js melalui komponen React yang mengelola instance dan cleanup; dependency dipin lewat package lockfile.
- Go menyediakan JSON API dan aset build React, tanpa halaman bisnis berbasis html/template.
- Database: PostgreSQL, driver pgx/v5 dengan connection pool.
- Migration: SQL up/down, migration runner yang benar-benar disertakan.
- Logging: structured logging, request ID, penyamaran credential.
- File lokal: private filesystem storage melalui interface Storage.
- Worker: binary Go terpisah; queue persisten di PostgreSQL.
- OpenClaw: Gateway yang sudah berjalan pada host Mac; adapter HTTP server-side.
- Export: CSV dan XLSX, library Go yang diverifikasi dan dipin.
- Test: Go unit/integration test, Vitest + React Testing Library untuk interaksi penting, serta browser smoke test/Playwright jika tersedia.
- Tidak membutuhkan Redis, Kafka, Kubernetes, atau service cloud untuk localhost.
Default alamat:
- Frontend development: http://localhost:5173
- Go API dan preview build React: http://localhost:8080
- PostgreSQL container: 127.0.0.1:5432
- OpenClaw lokal: http://127.0.0.1:18789
Jalankan app dan worker secara native pada Mac untuk fase awal; PostgreSQL melalui Docker Compose. Ini menghindari asumsi bahwa localhost di container menunjuk ke host Mac. Sediakan alternatif PostgreSQL native melalui DATABASE_URL.
Development: Vite mem-proxy /api ke Go pada 127.0.0.1:8080. Browser memakai URL relatif /api, sehingga cookie/session dan download attachment melalui origin frontend. Endpoint internal worker tetap dipanggil langsung pada Go; tidak diproxy untuk frontend. Local build preview: Go menyajikan frontend/dist dan API pada origin localhost:8080. SPA fallback hanya berlaku untuk route UI, bukan /api, /internal, health, atau request aset yang tidak ada. Font/icon/chart dibundel lokal; jangan mengandalkan CDN runtime.
Alur:
Admin -> React -> Go API -> storage privat + PostgreSQL jobs -> Go worker -> OpenClaw lokal -> hasil draft -> validasi backend -> review Admin -> publikasi -> dashboard/leaderboard/export.
Semua komponen localhost kecuali provider model yang dipilih. Jelaskan bahwa menjalankan Gateway lokal tidak otomatis membuat inference model lokal.

9. Queue, worker Go, idempotensi
Queue harus tetap ada setelah app atau worker restart. PostgreSQL menjadi penyimpanan antrean.
Claim pekerjaan atomik dengan transaksi dan locking yang sesuai, misalnya FOR UPDATE SKIP LOCKED. Gunakan lease token per claim, lease_until, heartbeat, attempt count, next_run_at, timeout, last_error, worker_id.
Worker mengambil job lewat internal API localhost. Worker hanya memegang machine credential; tidak perlu memiliki credential database. Server mengambil payload berdasarkan job yang sah.
Endpoint internal:
POST /internal/jobs/claim
POST /internal/jobs/{id}/heartbeat
GET /internal/jobs/{id}/attachments/{attachment_id}
POST /internal/jobs/{id}/result
POST /internal/jobs/{id}/failure
Machine auth terpisah dari user auth; setiap heartbeat/result menyertakan lease token yang aktif. Hasil dari lease lama setelah reclaim ditolak agar worker lama tidak menimpa pekerjaan baru.
Idempotency key memuat reporting subject, basis/periode, set attachment/content hashes, pipeline/mapping version. Hash sama di dua konteks berbeda hanya flag dugaan, bukan otomatis menggabungkan laporan. Request upload/retry/result aman terhadap pengiriman ulang.
Transient failure retry dengan backoff+jitter, maksimal tiga retry setelah attempt pertama; schema/bukti tidak terbaca meminta review, bukan retry tanpa batas.
Hanya satu extraction job aktif per logical input revision. Koreksi manual saat job berjalan memakai revision guard sehingga hasil job lama tidak menimpa koreksi baru.
Bersihkan temp file setelah job. Log hanya metadata aman. Kegagalan OpenClaw menyimpan error asli yang sudah disanitasi, memberi status gagal/perlu tindakan, dan tidak menghasilkan angka.
10. Adapter OpenClaw dan simulasi

TikTok contoh sumber:

perkiraan GMV 12.24M -> 12240000 dengan rounded precision;
impresi 2.42M -> 2420000;
tayangan 61.52K -> 61520;
orders 222; buyers 201;
watch duration 15 detik;
current viewers 128;
AOV 69.75K -> 69750 IDR;
product clicks 3.82K -> 3820;
followers 59;
likes 5.22K -> 5220;
comments 392; shares 56.
Ini angka ekstraksi fixture, bukan metrik Linda yang otomatis valid.
Room sekitar 06.00–18.00 dan slot Linda 16.00–18.00 harus menghasilkan SCOPE_MISMATCH.
Estimated GMV bukan indirect GMV.
Current viewers bukan total viewers.
AOV bukan otomatis Avg Price.
Watch PV/Show PV serta Direct GMV butuh definisi yang dikonfirmasi.
Simpan additional units_sold=270, CTR=0.0621, CTOR=0.0581,
ROI GMV Max=5.03, ad_cost=3340000 jika terlihat, sebagai source metrics terpisah.
Shopee fixture:

orders 1; buyers 1; watch duration 26 detik;
comments 49; add_to_cart 49; units_sold 1;
likes 228; shares 2; active viewers 61; peak viewers 8;
comment rate 0.05; click rate 0.159; orders/click 0.006;

Tanggal/periode yang terpotong perlu konfirmasi; contoh sumber tidak otomatis valid untuk host.

12. Perhitungan laporan deterministik
Bangun service/query bersama untuk dashboard, export, leaderboard, dan tools insight.
Filter dasar: date_from/date_to, timezone, channel, basis, currency,
brand dalam assignment untuk laporan privat, studio, host.
Leaderboard memakai filter global berbeda; tidak mewarisi brand filter.
Tanggal UI inklusif diubah ke interval query yang benar. Tren harian berdasarkan tanggal awal slot. Dokumentasikan aturan lintas tengah malam.
Aturan:
- Total Sesi = count slot unik final yang valid; room count metric terpisah.
- Jam live = jumlah detik slot eligible / 3600.
- Views = sum pada subset definisi kompatibel; bukan unique people.
- Interaksi = sum likes+comments+shares hanya slot dengan ketiga komponen valid.
- Jika tidak ada slot lengkap, total interaksi null; komponen masih bisa ditampilkan dengan coverage.
- Penjualan = sum compatible source_sales/GMV sesuai basis/mata uang.
- Buyer/viewer lintas sesi jika dijumlahkan diberi label jumlah per sesi, bukan orang unik periode.
- Views/sesi = sum views / count slot dengan views valid.
- Views/jam = sum views / sum duration pada subset pasangan valid.
- AOV = sum sales / sum orders pada subset kedua metric valid dan basis sama.
- GMV/jam = sum sales / sum duration pada subset pasangan valid.
- Rasio periode memakai sum numerator/sum denominator yang terverifikasi.
- Watch duration agregat hanya bila bobot sesuai definisi tersedia.
- Peak concurrent = maximum eligible metric, bukan sum.
- Conversion, ROAS, contribution mengikuti definisi dan subset sah.
- Penyebut nol atau tidak tersedia menghasilkan null/N/A.
- Baseline nol untuk perubahan persentase menghasilkan N/A, bukan infinity/100%.
- Missing tidak di-coalesce menjadi nol.
- Periode pembanding mempunyai panjang sama; source definition/basis kompatibel.
Return coverage untuk setiap metric: eligible slots, total relevant slots, missing slots, unit, basis, definition version, last updated, limitations.
Jangan membuat total lintas channel bila kontrak belum compatible. UI menawarkan pilihan channel eksplisit dan breakdown terpisah. Jangan menduplikasi room metrics ke tiap slot.
Untuk MVP query langsung dari versi final aktif lebih baik daripada cache rumit. Jika cache dipakai, scope dan key eksplisit, invalidasi setelah publish/revoke/revision, tidak ada kebocoran antarbrand.

Setelah publish/revise/revoke, invalidate query dashboard, sessions, metric details, leaderboard, host profile/compare, dan insight yang relevan. Jangan optimistic-update angka laporan final atau status publish sebelum backend mengonfirmasi. Master update boleh optimistic hanya jika rollback aman.

1 Tujuan dan arah solusi
Its My Live mengumpulkan laporan livestream untuk menilai jangkauan, interaksi, hasil penjualan, dan aktivitas live secara seimbang. Admin mengunggah bukti; AI mengekstrak data; backend memvalidasi sebelum publikasi. Brand melihat performa sendiri dan leaderboard global host ITS MY LIVE untuk menemukan kandidat host berdasarkan data dan konteks, lalu meminta insight melalui SapaGo.
Rekomendasi MVP: satu platform multi brand, ledger standar dengan pemetaan per channel, serta review Admin sebelum publikasi. Database menjadi sumber laporan utama. Google Sheets dapat menjadi acuan format atau tujuan ekspor jika dibutuhkan.
Interpretasi brief: “generate gambar ke ledger” berarti membaca gambar dan memindahkan nilai metrik ke kolom ledger, bukan membuat gambar baru. Gambar asli tetap disimpan sebagai bukti.
Batas informasi
Sumber revisi: screenshot dasbor LIVE zwitsal_id tanggal 26 September dan snapshot workbook Data Metric [Sirclo x Streamwise], sheet Performance Sirclo X Streamwise. Header A2:AG2 berisi 33 kolom; contoh data terisi ada di baris 4 dan 5. Isi ini berasal dari lampiran, bukan verifikasi versi terkini Google Sheets. Pemetaan rinci dan konflik sumber tercantum pada bagian 9 sampai 11. Integrasi OpenClaw dan SapaGo tetap memerlukan uji teknis.
2 Alur utama
1. Admin memilih brand, channel, studio, host, tanggal, jam sesi, lalu mengunggah satu atau beberapa lampiran.
2. Backend menyimpan sesi dan bukti asli, memeriksa duplikasi, lalu membuat pekerjaan ekstraksi di antrean.
3. OpenClaw sebagai orchestrator yang diusulkan menjalankan ekstraksi lewat model yang mendukung gambar. Hasil tersimpan sebagai draft terstruktur beserta sumbernya.
4. Sistem memeriksa field, tipe angka, satuan, periode, dan kelengkapan. Admin membandingkan hasil dengan lampiran, memperbaiki bila perlu, lalu mempublikasikan.
5. Sistem menghitung metrik berdasarkan definisi ledger dan memperbarui dashboard. AI menyusun insight dari data yang telah dipublikasikan.
6. Brand login, memilih periode dan filter, melihat dashboard, mengekspor laporan, atau bertanya melalui widget SapaGo.
   3 Input sesi dan struktur ledger
   Data ledger minimum
   Setiap baris ledger mewakili slot host yang diinput Admin. Bukti dapat mencakup satu room LIVE dengan durasi lebih panjang. Simpan host_slot_id, live_room_id jika tersedia, cakupan dan waktu laporan sumber, serta relasi bukti ke slot. Ledger host hanya boleh dipublikasikan jika cakupan metrik cocok dengan slot; total room disimpan terpisah dari total slot agar tidak dijumlahkan ulang.
   Jejak ekstraksi memuat teks/nilai asli, nilai normalisasi, attachment_id, halaman atau lokasi bukti, versi mapping, versi pemrosesan, serta status validasi. Versi final memuat reviewer, waktu publikasi, dan alasan koreksi. Metrik yang tidak tersedia disimpan kosong, tidak diubah menjadi nol.
   Entitas utama
   User dan akses brand; Brand dan akun channel; Channel; Studio; Host; Room LIVE; Slot host; Lampiran dan cakupan sumber; Pekerjaan ekstraksi; Hasil ekstraksi; Ledger dan versi; Definisi metrik; Konfigurasi dashboard; Riwayat ekspor dan audit.
   4 Business rules proses data
   Otorisasi memakai role, cakupan data, dan izin aksi. Laporan brand, bukti, dan detail sesi tetap terbatas pada brand yang ditugaskan. Pengecualian resmi: semua akun brand/client aktif dapat membaca ringkasan host global yang sudah dipublikasikan pada modul Leaderboard Host. Aturan ini berlaku di backend, ekspor, dan tools AI.
   Admin hanya dapat memilih master data dalam cakupan aksesnya. Brand dengan banyak akun channel tetap memakai satu brand_id; nama akun bukan kunci akses.
   Cek duplikasi melalui ID Line, hash lampiran, dan kombinasi akun channel serta waktu sesi. Dugaan duplikat meminta review; jangan otomatis menolak sesi berbeda yang sah.
   Ekstraksi hanya mengambil nilai yang terlihat pada bukti. AI tidak boleh mengisi angka yang hilang, memperkirakan hasil penjualan, atau menganggap GMV sama dengan omzet bersih.
   Normalisasi mendukung pemisah ribuan/desimal, Rp, K dan M hanya bila konteks sumber jelas. Angka ambigu, gambar tidak terbaca, periode berbeda, atau mata uang tidak jelas wajib direview.
   Beberapa lampiran satu sesi saling melengkapi. Jika angka metrik yang sama berbeda, tandai konflik dan tentukan sumber final; jangan menjumlahkan screenshot yang tumpang tindih.
   Status proses: Draft, Antrean, Diproses, Perlu Review, Siap Publikasi, Dipublikasikan, Gagal, Diarsipkan. Hasil AI yang lolos validasi tetap memerlukan persetujuan Admin pada MVP.
   Data draft tersimpan terpisah secara logis dari ledger final. Dashboard brand, ekspor brand, dan insight AI hanya memakai versi yang dipublikasikan.
   Admin dapat mengoreksi draft. Koreksi laporan yang sudah terbit membuat versi baru dengan alasan perubahan; versi lama tetap aktif sampai pengganti dipublikasikan.
   Pekerjaan gagal menampilkan alasan dan opsi retry. Usulan maksimal 3 retry otomatis untuk gangguan sementara; kesalahan bukti membutuhkan perbaikan Admin. Retry tidak boleh menggandakan ledger.
   Master data yang sudah dipakai dinonaktifkan, bukan dihapus permanen. Riwayat sesi mempertahankan identitas dan konteks saat laporan diterbitkan.
   Publikasi mensyaratkan definisi dan cakupan metrik cocok dengan ledger. Screenshot sepanjang room LIVE tidak boleh dipakai sebagai hasil slot host yang lebih pendek. Hanya data dengan periode, definisi, dan mata uang kompatibel yang boleh digabung; koreksi menghitung ulang agregat dan menandai insight lama kedaluwarsa.
   Pemisahan tanggung jawab
   AI membaca bukti, mengusulkan mapping, dan menjelaskan insight. Backend memvalidasi data, mengendalikan izin, menghitung metrik, serta mempublikasikan versi final. OpenClaw menerima akses melalui API terbatas; tidak diberi akses database tanpa pembatasan.
   5 Role dan permission
   Satu user dapat ditugaskan ke beberapa brand. Laporan brand tetap mengikuti assignment; semua brand/client aktif mendapat akses modul Leaderboard Host global. Izin global ini hanya mencakup profil host dan agregat yang disetujui, bukan laporan atau lampiran brand lain. Admin tidak dapat menaikkan role sendiri atau mengubah izin global.

   Metrik sumber ledger terdapat pada kolom P sampai AC. Bagian 11 menentukan mapping dan batasnya. Tabel berikut berisi aturan agregasi umum serta kandidat pengembangan dashboard; GMV gabungan, conversion rate, CTR, dan ROAS hanya diaktifkan setelah definisi sumber disepakati.

   7 Insight AI dan kebutuhan development
   Aturan chat SapaGo
   Usulan integrasi: widget memakai identitas login yang diverifikasi backend dan tools laporan yang dibatasi berdasarkan user serta brand. Brand_id dari browser atau teks chat tidak dipercaya sebagai bukti akses. Kemampuan autentikasi widget dan tool SapaGo harus diuji terlebih dahulu.
   AI menyebut periode, metrik, dan cakupan sumber; membedakan fakta dan dugaan. Tools laporan brand tetap memakai assignment; tools leaderboard global hanya membaca agregat yang diizinkan. Permintaan rekomendasi host mempertimbangkan jangkauan, interaksi, omzet, jumlah sesi, dan cakupan. AI tidak memberikan label host buruk, skor potensi buatan, atau mengungkap rincian brand lain. Tanpa sampel memadai, AI menjelaskan keterbatasan perbandingan.
   Paket pekerjaan MVP
7. Fondasi aplikasi — login, role, assignment brand, otorisasi API, pengelolaan user, dan audit aktivitas. Hasil: setiap user hanya memperoleh data dalam cakupan akses.

11. Review dan ledger — perbandingan gambar dengan hasil AI, penanda konflik, edit manual, publish, versi koreksi, serta definisi mapping per channel.
12. Perhitungan laporan — rumus deterministik, agregasi sesuai definisi, filter akses, penanganan data kosong, dan pembaruan setelah publikasi.
13. Dashboard dan ekspor — KPI jangkauan, interaksi, aktivitas, dan penjualan yang seimbang; tren; tabel sesi; leaderboard host global yang dapat diurutkan menurut beberapa metrik; profil agregat host; serta ekspor sesuai cakupan.

    Urutan implementasi
    Tahap 1: ledger, hak akses, upload, dan input/koreksi manual. Tahap 2: ekstraksi AI dan review. Tahap 3: dashboard, ekspor, serta insight dan widget SapaGo setelah uji akses. Jalankan pilot pada satu channel dan sejumlah brand terbatas sebelum menambah variasi format laporan.

    18 Arahan UI dan UX dashboard user
    Tujuan tampilan: brand memahami performa livestream miliknya secara menyeluruh, lalu menjelajahi host ITS MY LIVE sebagai kandidat. Gunakan desain minimal, tenang, dan mudah dipindai. Persyaratan berikut menjadi brief implementasi UI; contoh angka harus diberi label Data contoh dan tidak diklaim sebagai laporan aktual.
    Navigasi dan hierarki informasi
    Sidebar ringkas berisi Ringkasan, Laporan Sesi, Leaderboard Host, dan Insight. Header memuat brand aktif untuk laporan sendiri, pemilih periode, serta Ekspor. Halaman Leaderboard Host mengganti brand picker lokal dengan label Seluruh ITS MY LIVE. Konteks global selalu terlihat agar user tidak mengira ranking hanya berasal dari brandnya.
    Definisi dan aturan tampilan
    Total Views = jumlah views sesi final dengan definisi kompatibel; bukan jumlah orang unik. Total Interaksi = likes + komentar + shares dari subset sesi yang memiliki ketiga nilai valid. Bila komponennya belum lengkap, tampilkan komponen terpisah dan cakupannya; jangan memberi total seolah lengkap. Total Sesi memakai slot unik final; jumlah LIVE room tersedia sebagai metrik berbeda. Penjualan memakai basis pesanan dan mata uang yang sama.
    Total jam dan durasi sesi dihitung dari waktu slot. Rata-rata views per sesi memakai total views ÷ jumlah slot yang memiliki views valid. Views per jam memakai subset slot yang memiliki views dan durasi valid. Watch duration dan rasio periode hanya tampil bila bobot atau pembilang/penyebut tersedia. Jika channel tidak kompatibel, grafik dipisah per channel dan KPI gabungan tidak ditampilkan.

    Latar #F7F8FA, permukaan putih, teks #1F2937, garis #E5E7EB, satu aksen teal #0F766E. Font Inter dengan fallback sistem. Ukuran isi 14–16 px, judul 24–28 px, angka KPI 28–32 px; angka tabel rata kanan. Spasi kelipatan 8 px, radius 10–12 px, border tipis, bayangan sangat ringan. Ikon outline sederhana; warna seri grafik konsisten dengan legenda dan label.
    Hindari gradient besar, glassmorphism, ilustrasi dekoratif, kartu berlebihan, podium, warna emas untuk omzet, atau panel AI dominan. SapaGo menjadi tombol bantuan ringkas yang membuka drawer; insight disertai periode dan sumber. Desain menonjolkan data dan kontrol yang dipakai user.

Metrik
Aturan perhitungan
Peringkat metrik aktif
Urutkan nilai valid terbesar pada metrik yang dipilih. Nilai sama memakai ranking sama, misalnya 1, 2, 2, 4. Nama host hanya menentukan urutan tampilan.
Total omzet host
Jumlah GMV pada ID slot unik, versi aktif, telah dipublikasikan, dan atribusi host valid.
Kontribusi omzet
Omzet host ÷ total omzet seluruh host global yang memenuhi syarat pada filter aktif × 100%. Tidak dibatasi brand yang login.
Slot valid dan jam live
Jumlah slot unik dan durasinya; tampilkan juga jumlah slot yang mendukung setiap metrik agar sampel berbeda terlihat.
Omzet per jam dan per slot
Total omzet ÷ jam live, atau ÷ jumlah slot valid. Penyebut nol menghasilkan N/A.
Pesanan dan AOV
Pesanan hanya dari slot dengan nilai valid. AOV memakai GMV ÷ pesanan pada subset slot yang memiliki kedua metrik dengan basis sama.
Cakupan data
Slot dengan GMV valid ÷ seluruh slot host tercatat pada periode/filter aktif. Tampilkan agar hasil parsial dapat dikenali.
